# FoxTunnel

**[English](README.en.md)**

FoxTunnel — экспериментальный прокси-сервер и клиент. Он передаёт соединения через HTTPS и открывает локальный **SOCKS5-прокси** для приложений. Есть несколько транспортов, в том числе HTTP/2 и HTTP/3.

**Важно:** это пока не готовый VPN «для всего устройства». UDP и Linux TUN существуют в экспериментальном режиме. Работа при сетевых блокировках, совпадение с Firefox и отсутствие всех утечек **не гарантируются**.

## Быстрый старт

**1. Получите программу.** Выберите архив для своей системы в [GitHub Releases](https://github.com/SawaMEN/FoxTunnel/releases) или соберите из исходников (Go 1.26+):

~~~bash
go build -o foxtunnel ./cmd/foxtunnel
./foxtunnel version --json
~~~

Доступные платформы и состав архивов зависят от версии. Экспериментальная сборка **Go + NSS + Neqo** опубликована как [v0.1.0-alpha.2](https://github.com/SawaMEN/FoxTunnel/releases/tag/v0.1.0-alpha.2) для **Linux amd64**. Это сборка до последнего объединения веток, а не гарантированно актуальный бинарник из \`main\`.

**2. Подготовьте сервер.** Нужны собственный домен, DNS-запись и действующий TLS-сертификат с ключом:

~~~bash
./foxtunnel setup --server https://vpn.example.com \
  --cert /path/to/fullchain.pem \
  --key /path/to/privkey.pem \
  --out server-config

./foxtunnel server --config server-config/server.json
~~~

**3. Подключите клиент.** Перенесите \`server-config/connection.txt\` на клиент **по защищённому каналу** и запустите:

~~~bash
./foxtunnel client --link-file connection.txt
~~~

По умолчанию SOCKS5 доступен по адресу \`127.0.0.1:1080\`. Укажите его в настройках браузера или приложения.

**Файл \`connection.txt\` содержит пароль.** Не публикуйте его, не присылайте в issue и не сохраняйте в Git.

Полные действия по установке, сертификатам и проверке подключения — в **[Быстром старте](docs/START.md)**.

## Что умеет

- **TCP:** локальный SOCKS5 → зашифрованное соединение → FoxTunnel-сервер.
- **Транспорты:** HTTP/2, HTTP/3, WebSocket и XHTTP.
- **Mozilla Engine:** NSS для TLS/HTTP2 и экспериментальный Neqo для HTTP3/QUIC; включается отдельно, нужна подходящая сборка.
- **UDP и Linux TUN:** доступны по явному включению; сетевые маршруты, системный DNS и блокировка утечек настраиваются отдельно.
- **Дополнительно:** несколько серверов, объединение каналов, управление доступом, Go SDK.

Обычный режим работает без флага \`--engine\`. Чтобы использовать экспериментальную Mozilla-сборку:

~~~bash
./foxtunnel client --engine mozilla --link-file connection.txt
~~~

Режим Mozilla **не означает**, что весь трафик автоматически пойдёт по HTTP/3: транспорт из файла подключения сохраняется. Правила выбора и параметры описаны в [Возможностях и настройках](docs/FEATURES.md).

**Экспериментальная оптимизация нод:** отдельные режимы выбора входов, Smart Multi-Hop и Adaptive Bonding с AutoTune. Флаги выключены по умолчанию; реальное ускорение не подтверждено. [Настройка и ограничения](docs/NODES.md).

## Текущее состояние

FoxTunnel находится в разработке. Сборка и локальные CI-проверки HTTP/2, HTTP/3 и Linux TUN проводились, но это **не** доказательство надёжности на конкретных VDS или мобильных операторах. Не используйте экспериментальные режимы там, где требуется сертифицированная защита от утечек.
