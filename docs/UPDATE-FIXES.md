|---|---|---|

## Возобновление сессий

HTTP/2 NSS использует внешний token cache вместо process-wide NSS cache.
В каждом транспорте максимум восемь записей, по одному одноразовому билету
на address/SNI/ALPN/profile. NSS-токен ограничен 64 КиБ, сохранённая цепочка —
1 МиБ. Истёкшие билеты отбрасываются. `SessionTicketsDisabled` запрещает кэш;
отдельный `DialTLSContextWithProfile` (WSS) по-прежнему не использует кэш.
NSS 0-RTT явно выключен.

Neqo также хранит максимум восемь одноразовых билетов отдельно для каждого
транспорта и origin/SNI. Native token — максимум 64 КиБ, цепочка — 1 МиБ,
срок — не больше срока NSS-токена и 24 часов. Rust ABI изменён с 1 на 2:
добавлены import/reverification и событие билета, в Connected передаётся
факт resumption. Старая библиотека отвергается до создания транспорта.

В обоих адаптерах resumed handshake повторно проверяет сохранённую цепочку:
CA, hostname, срок сертификата, `tls.Config.Time` и `VerifyConnection`/pinning.
Повторное использование TLS PSK не разрешает HTTP до завершения проверки.
Билеты не сохраняются на диск и не попадают в отчёты.

Закреплённый Neqo 0.33.0 автоматически разрешает 0-RTT при import токена и
может отправлять собственные H3 control streams до завершения handshake.
Публичного переключателя отключения у него нет. FoxTunnel не создаёт
HTTP-запросы, streams с credentials или request body до Connected и успешной
повторной проверки. Отказ сервера от early data не повторяет запрос: таких
запросов ещё не было. Это не заявление об отключении всего QUIC 0-RTT.

## Параметры Firefox

Вместо прежних 90 секунд/4096/16 Neqo использует измеренные у Firefox 158
idle timeout 30 секунд, QPACK decoder/encoder table 65536 и blocked streams
20. Go pool перестаёт выдавать простаивающее соединение после 25 секунд.
QPACK таблицы всё ещё ограничены; память для них может вырасти относительно
прежнего лимита 4 КиБ.

Лимит receive window 1 МиБ и запрет миграции сохранены: первый ограничивает
буферизацию, второй соответствует connected UDP socket текущего адаптера.
Увеличение окна до Firefox 24 МиБ и разрешение неподдерживаемой смены peer
не являются частью исправления. ALPN h2-only и TLS 1.3-only также остаются
протокольными ограничениями NSS-транспорта.

Контролируемый стенд дополнительно снимает `nss-firefox` с явно включёнными
TLS и H2 profiles `firefox-158`. Его JSON, hashes, поведение и различия
с Firefox сохраняются отдельно от native default. Совпадение отдельных
settings не подтверждает полную эквивалентность Firefox или DPI-профиля.

## UDP-буферы

Раньше reader читал UDP в один буфер и выделял/копировал каждый пакет для
очереди. Теперь он читает сразу в слот из пула: восемь слотов в очереди,
один у reader и один у actor. После синхронного `ftn_input` actor возвращает
слот. Native не сохраняет Go pointers. Каналы передают исключительное
владение; reader не перезаписывает пакет во время native-вызова.

На одно соединение выделяется фиксированно около 640 КиБ receive storage.
Пул принадлежит соединению и освобождается вместе с ним; глобального
неограниченного pool нет. Изменение устраняет одну Go allocation и одну
копию на входящий пакет. Ускорение WAN или снижение RSS не заявляется.

## Проверки

Локально прошли NSS resumption с race detector, отказ после смены pinning
и истечения сертификата, изоляция двух транспортов, отключение tickets,
лимиты/одноразовость cache, NSS/tunnel race tests и Go vet адаптера.
Neqo интеграционные тесты положительного resumption, изоляции,
смены CA/pinning/срока и сервера, разрешающего 0-RTT, прошли в
[CI 39737672043](https://github.com/SawaMEN/FoxTunnel/actions/runs/39737672043).
Там же прошли Rust fmt/clippy/ABI, race и cgocheck, native metrics и browser
workload. Сервер зафиксировал resumption в обоих повторных соединениях NSS/H2
и Neqo/H3 (2/2); отдельный NSS firefox-158 profile тоже 2/2.
Артефакт native-wire-observations: SHA-256
`5e8518ef0d5c3c3f9ffb55f05156354c628b8d769dfd4bf6424f6cbcd8a19d2c`.
Этот прогон относится к update до объединения с firefox; объединённый код
проверяется отдельно при слиянии.

Историческое сравнение этапа 5 остаётся в сохранённых JSON. Оно не
пересобирается со старым Go ABI 1 против новой библиотеки ABI 2. Текущий
профиль ресурсов и browser workload по-прежнему выполняются в native CI.
