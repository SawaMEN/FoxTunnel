# Возможности и настройки

[На главную](../README.md) · [Быстрый старт](START.md) · [English](FEATURES.en.md)

Здесь собраны все основные возможности. Для первого подключения достаточно [Быстрого старта](START.md): дополнительные функции **не обязательны**.

## Как работает FoxTunnel

~~~text
Приложение → SOCKS5 (127.0.0.1:1080) → FoxTunnel-клиент
           → защищённый HTTPS-транспорт → FoxTunnel-сервер → сайт
~~~

Клиент и сервер используют TLS 1.3 и авторизацию. По умолчанию FoxTunnel обслуживает TCP-запросы приложений, настроенных на SOCKS5. При передаче данных сервер видит назначения; это **не анонимная сеть**.

## Транспорты — что выбрать

| Режим | Для чего | Особенности |
|---|---|---|
| \`h2-connect\` | Обычный TCP-туннель | Базовый выбор по умолчанию |
| \`h2-post\` | TCP через HTTP/2 POST | Другой способ передачи потоков |
| \`h3-post\` | TCP через HTTP/3/QUIC | Требует доступного UDP-порта |
| \`wss\` | TCP через WebSocket/TLS | Требует совместимого сервера |
| \`xhttp-stream-one\`, \`xhttp-stream-up\`, \`xhttp-packet-up\` | Варианты XHTTP | Экспериментальные |

Не меняйте транспорт «наугад». У клиента и сервера должен быть совместимый режим. При использовании \`--link-file\` транспорт берётся из файла подключения.

## Go, NSS и Neqo — в чём разница

- **Go TLS / quic-go:** обычная реализация, доступная в стандартной Go-сборке.
- **NSS:** библиотека Mozilla для TLS-соединений. Не содержит весь браузер Firefox.
- **Neqo:** реализация Mozilla QUIC/HTTP/3 на Rust. Работает в отдельной экспериментальной Linux amd64 сборке вместе с NSS.
- **Mozilla Engine:** выбирается через \`--engine mozilla\` или Go SDK. Для TCP/H2 использует NSS, для поддерживаемого HTTP/3 — Neqo. При явно неподдерживаемом варианте выдаёт ошибку.

~~~bash
./foxtunnel client --engine mozilla --link-file connection.txt
~~~

Режим Mozilla **не меняет транспорт, записанный в connection.txt**. Для ручной конфигурации без файла можно указать \`--transport h3-post\` и подобрать совместимые параметры через \`--help\`.

Если настроен Neqo с резервным H2, переключение происходит только при подтверждённой недоступности H3 **до отправки запроса**. Ошибка сертификата, SNI или pin не разрешает небезопасный обход TLS.

Локальная диагностика: \`--engine-status-interval 10s\`. Она выдаёт агрегированные счётчики; по умолчанию выключена. SDK поддерживает \`Status()\` и \`NotifyNetworkChange()\`.

**Ни NSS, ни Neqo не гарантируют совпадение сетевого отпечатка Firefox или обход фильтрации.** Лабораторное совпадение отдельных HTTP/2 SETTINGS не доказывает совпадение TLS/QUIC и поведения браузера.

## Экспериментальный UDP

По умолчанию **выключен**. Для нового сервера включайте при \`setup\`:

~~~bash
./foxtunnel setup --server https://vpn.example.com \
  --cert /path/to/fullchain.pem --key /path/to/privkey.pem \
  --enable-udp --out server-config
./foxtunnel server --config server-config/server.json
~~~

На клиенте:

~~~bash
./foxtunnel client --link-file connection.txt --enable-udp
~~~

Это базовый UDP запрос/ответ. Для более длительного мультиплексированного UDP-потока:

~~~bash
./foxtunnel client --link-file connection.txt --enable-udp --udp-stream
~~~

Сервер также должен поддерживать UDP. Режимы имеют лимиты пакетов, потоков и направлений. Они **не равнозначны нативному UDP VPN**, не подходят без проверки для игр, звонков и сетей с потерями.

## Экспериментальный Linux TUN

Можно включить встроенный TUN, направляющий TCP/UDP через локальный FoxTunnel-клиент:

~~~bash
./foxtunnel client --link-file connection.txt \
  --enable-udp --udp-stream --tun ftun0 --tun-mtu 1400
~~~

Требуются Linux, \`/dev/net/tun\`, права \`CAP_NET_ADMIN\` и сервер с включённым UDP. Встроенный режим использует Go TCP/IP стек; отдельный sing-box не нужен.

**Очень важно:** FoxTunnel не прописывает маршруты, системный DNS и kill switch автоматически. Неправильные маршруты могут запустить туннель через самого себя; неверный firewall может оборвать SSH или оставить трафик вне туннеля. Экспериментируйте только на локальном или изолированном Linux-хосте с консольным доступом и отдельным маршрутом к IP сервера.

Существующий альтернативный Linux TUN companion на sing-box — отдельный эксперимент, а не обязательная часть FoxTunnel.

## Несколько серверов и пользователи

FoxTunnel поддерживает резервные входы, кластерный список нод и bond-каналы. Для начала используйте **один сервер**: дополнительные входы требуют общих настроек, доверенной главной ноды и отдельной диагностики. \`foxtunnel setup\` также создаёт \`node.json\` для нод.

На сервере доступен управляемый доступ по пользователям с лимитами соединений, запросов и трафика. Не смешивайте его с простым режимом одной пары логин/пароль. Точные параметры текущей версии всегда можно проверить через \`foxtunnel server --help\` и \`foxtunnel access --help\`.

## Безопасность и ограничения

- TLS проверяет цепочку сертификата, срок, имя сервера (SNI) и при необходимости дополнительный SPKI pin. **Не отключайте проверку сертификата.**
- \`connection.txt\` содержит пароль — храните как секрет. При утечке замените учётные данные.
- Сервер должен разрешать выход только на необходимые назначения; частные и локальные IP по умолчанию ограничены. Никогда не открывайте \`--allow-private\` на публичной прокси без строгой изоляции.
- Локальный SOCKS5 по умолчанию не имеет отдельной авторизации. **Оставляйте \`--listen 127.0.0.1:1080\`**, а не публикуйте его в сеть.
- UDP/TUN и маршруты требуют отдельной настройки DNS/firewall. Kill switch в FoxTunnel не встроен.
- Любые отчёты об «ускорении» на loopback не равны внешним измерениям. В реальных мобильных сетях протокол не был универсально подтверждён.

Для публичного сервера обязательно используйте обновляемые сертификаты, отдельную учётную запись процесса, ограничения доступа и резервные копии приватной конфигурации.
