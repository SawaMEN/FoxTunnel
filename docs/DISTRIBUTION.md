# Самостоятельные версионные бинарники

**Русский** | [English: полный контракт и команды](DISTRIBUTION.en.md)

FoxTunnel поставляется как отдельный исполняемый файл. Любая панель, включая
3x-ui, или клиент на другом языке сможет скачивать конкретную версию и управлять
её процессом. Код панели, её БД, Xray или закрытый сервис не требуются. Go SDK —
дополнительный способ встраивания.

Подготовлен pipeline GitHub Releases. Само изменение ещё не создаёт релиз:
после слияния workflow тег `vMAJOR.MINOR.PATCH[-pre]` запускает сборку, проверку
всех артефактов и публикацию экспериментального prerelease. На PR выполняются
те же сборки без публикации релиза. Ошибка/отсутствие одной платформы блокирует
публикацию; существующий релиз не перезаписывается. `v0.0.0-ci` — тестовая версия.

| ОС | Архитектуры | Варианты |
|---|---|---|
| Linux | amd64, arm64 | go и nss |
| Linux | armv7 | go |
| macOS | amd64, arm64 | go |
| Windows | amd64, arm64 | go |

Всего девять архивов. Go-сборки используют CGO=0; Linux NSS-сборки требуют системных
libnss3/libnspr4 и совместимой среды (в CI Ubuntu 24.04), библиотеки не упакованы
внутрь. Ни один вариант пока не воспроизводит полный Firefox. Даже NSS-сборка
сохраняет CLI backend `go` по умолчанию: NSS выбирается флагом или настройкой ссылки.
Linux проходит нативные проверки; macOS/Windows — кросс-компиляцию, без утверждения
полной проверки на этих ОС. Подписи исполняемых файлов и notarization пока нет.

Имена: `foxtunnel_VERSION_OS_ARCH_FLAVOR.tar.gz`, для Windows `.zip`. В имени
нет начального `v`; в manifest версия совпадает с тегом целиком. В архив входят
бинарник, `build.json`, MIT-лицензия и лицензии Go/использованных модулей. Рядом
публикуются `manifest.json` schema 1 и `SHA256SUMS`: версия, commit, target,
имя/размер/SHA-256, требования runtime и статус нативной проверки. Смешанные
версии/commit, dirty-сборки, неполная матрица и неверные хеши отклоняются.

Алгоритм для панели:

1. Выбрать точный поддерживаемый тег, а не `latest`.
2. Скачать manifest по `/releases/download/TAG/manifest.json` доверенного репозитория.
3. Найти `OS/ARCH/FLAVOR`, проверить требования runtime, скачать указанный архив.
4. Проверить размер/SHA-256, распаковать в отдельный каталог версии с проверкой путей.
5. Запустить `foxtunnel version --json`; сверить schema, версию, commit, CPU/ОС,
   protocol draft и доступность нужного TLS backend; dirty-релиз отклонить.
6. Запустить `client --link-file PRIVATE_FILE --listen 127.0.0.1:1080` или
   `server --config PRIVATE_SERVER_JSON`. Секреты передавать файлами/env/argv без shell.
7. Управлять процессом и маршрутизацией со стороны приложения. При обновлении
   остановить старую версию и сохранить её для отката: потоки не мигрируют.

x86_64 соответствует amd64, aarch64 — arm64, armv7l — armv7. Неподдерживаемые
архитектуры/варианты не подменяются автоматически. Все команды CLI, включая
setup/share/cluster-add, остаются в одном бинарнике.

JSON версии содержит также сведения Go, ARM variant, build flavor, TLS backends,
признак experimental и идентификатор `foxtunnel-draft-0`. Дополнительные поля
допускаются, неизвестная schema/draft — нет. Совместимость чернового протокола/API
пока не обещается автоматически: интегратор закрепляет проверенную версию.
Контрольная сумма проверяет целостность; отдельного контракта подписей пока нет.

Команды локальной сборки и детали pipeline — в английской версии. `--allow-dirty`
допустим только для локального preview: индекс релиза такую сборку не принимает.
