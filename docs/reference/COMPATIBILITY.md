# Совместимость и первый экспериментальный выпуск

**Русский** | [English](COMPATIBILITY.en.md)

FoxTunnel остаётся экспериментальным. До стабилизации wire/API интегратор
закрепляет точную версию, source commit, транспорт и TLS backend. Одинаковый
`foxtunnel-draft-0` не обещает совместимость всех экспериментальных коммитов.

| Контракт | Текущее правило |
|---|---|
| CLI | Команды/флаги не локализуются; человекочитаемые сообщения не являются API |
| `version --json`, `build.json` | Schema 1; неизвестные дополнительные поля допустимы, неизвестная schema отклоняется |
| Wire | `foxtunnel-draft-0` — описание реализации, без согласования версии по сети |
| Go SDK | Закрепляется точный тег/commit; стабильность API до v1 не обещается |
| `vetroff://` | Ссылка содержит секрет; неизвестные поля отклоняются, импорт не отключает TLS-проверки |
| Mozilla | Release NSS runtime закреплён отдельно от протокола; обновляется новым выпуском |

Несовместимое изменение формата требует новой спецификации, явного решения о
согласовании/отказе и тестов старый клиент ↔ новый сервер в обоих направлениях.
Нельзя менять байты обмена, оставляя прежний draft как обещание совместимости.
При отсутствии этих тестов новая версия публикуется только как экспериментальная,
с явным указанием проверенной пары. Сервер и клиент одной версии — первая
поддерживаемая тестовая комбинация; внешняя реализация пока не сертифицирована.

## Проверка скачанного комплекта

Нужен Python 3.11+. Скрипты `scripts/release.py`, `release_verify.py` и
`mozilla_runtime.py` берутся из проверенного checkout. Верификатор работает без
сети, не распаковывает архивы и не запускает содержащиеся в них файлы.

1. Из доверенного источника выбрать точный тег и полный source commit.
2. Скачать один из двух поддерживаемых Linux NSS-архивов `.tar.gz`.
3. Выполнить проверку (переменные ниже заранее заданы оператором):

```sh
python3 scripts/release.py verify --input downloaded \
  --version "$RELEASE_TAG" --commit "$RELEASE_COMMIT" --target linux/arm64/nss
```

Без `--target` проверяются оба архива. При выборе одного target нужен только его архив. Внешние `SHA256SUMS` и `manifest.json` не используются; CI хранит служебные `*.metadata.json` только на этапе сборки. Верификатор сравнивает `build.json` из архива с ожидаемыми version/commit/schema/draft, проверяет содержимое, безопасность путей и NSS provenance, не исполняя файлы.

**Ограничение целостности:** встроенный `build.json` сам по себе не подтверждает подлинность архива. Сверяйте источник скачивания и ожидаемый commit по независимому доверенному каналу; подписи/attestations пока не реализованы.

## Критерии первого тега

- Чистый проверенный commit, точные зависимости `go.mod/go.sum`, Go 1.26.9 в CI,
  Mozilla lock с URL/хешами бинарного/исходного архивов и лицензий.
- На том же commit проходят Go vet/race, внешний потребитель SDK, Python-проверки;
  обе нативные NSS-задачи проверяют передачу и контейнер без системных NSS/NSPR.
- Собраны две Linux NSS-цели; локальный index и независимый verify проверили содержимое архивов.
- macOS, Windows и armv7 исключены из публикуемой матрицы релизов.
- Тег указывает именно на этот commit; workflow выпускает только prerelease.
  Существующие архивы не заменяются. До создания тега CI-комплект не является релизом.
- Обновление использует отдельный каталог версии и сохранённую конфигурацию для
  отката; открытые TCP-потоки между версиями не переносятся.

Это воспроизводимый процесс получения и проверки комплекта, не гарантия побитовой
идентичности на разных компиляторах/ОС. База Linux NSS — Ubuntu 24.04; старые glibc
требуют отдельной проверки. План обновления Mozilla и Go входит в сопровождение.
