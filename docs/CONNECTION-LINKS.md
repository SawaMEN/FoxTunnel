# Ссылки подключения vetroff://

**Русский** | [English](CONNECTION-LINKS.en.md)

Единая схема подключения — **`vetroff://`**. Одна ссылка содержит один HTTPS-сервер
либо список до восьми доверенных нод, учётные данные и настройки клиента.
Формат используется командами `share` и `client`; регистрация обработчика ссылок
в Android, Windows и других ОС пока не реализована.

## Создание ссылки

`setup` создаёт ссылку и серверный JSON автоматически: [инструкция](SETUP.md).
Дополнительно поддерживаются `--sni`, `--pin-sha256` и `--encryption tls13`.
В JSON это `sni`, `pin_sha256`, `encryption`. SNI по умолчанию берётся из URL,
pin необязателен и дополняет CA/hostname-проверку. Шифрование — только TLS 1.3;
закрытый ключ сервера не передаётся. Настройки относятся к первому серверу/
координатору; у входов отдельные SNI/pin в составе кластера. Подробнее —
[матрица защиты](SECURITY.md). Старые ссылки работают с безопасными значениями
по умолчанию; старые клиенты отклоняют новые неизвестные поля.

Для одной главной ноды используйте `share --server https://main.example --bond --discover`.
В ссылке будет один сервер и `"discover":true`: входы и веса выдаёт главная нода.
См. [настройку кластера](CLUSTER.md). Без discovery объединение требует явного
списка хотя бы двух входов; с discovery допускается один действующий путь.

Сначала задайте `FOXTUNNEL_USER` и `FOXTUNNEL_PASSWORD`, как для обычного клиента.
Команда выводит только ссылку в стандартный вывод, не запуская сеть:

```sh
./foxtunnel share --server https://node-a.example
```

Несколько нод с объединением и автоматическим конвейером:

```sh
umask 077
./foxtunnel share --server https://node-a.example \
  --fallback-server https://node-b.example --bond \
  --bond-pipeline auto > connection.txt
```

Ссылка содержит пароль. Base64url — кодирование, не шифрование: передавайте её
как секрет. `umask 077` в примере ограничивает доступ к создаваемому файлу.
Пути сертификатов CA, адрес локального SOCKS5 и язык интерфейса не экспортируются.

## Подключение

Из файла, без переменных с учётными данными:

```sh
./foxtunnel client --link-file connection.txt
```

Из stdin:

```sh
./foxtunnel client --link-file - < connection.txt
```

Также поддерживается `--link 'vetroff://...'`. Файл/stdin предпочтительнее,
поскольку аргументы командной строки могут быть видны в списке процессов.
Содержимое корректно импортируемой ссылки не выводится в журнал; ошибки разбора
также не включают ссылку, JSON или пароль.

Настройки ссылки являются источником параметров подключения. Их нельзя смешивать
с `--server`, `--fallback-server`, `--bond` и другими флагами подключения.
Разрешены локальные `--listen`, `--ca-cert` и `--lang`:

```sh
./foxtunnel client --link-file connection.txt --listen 127.0.0.1:1080 --lang ru
```

Локальные пути CA не извлекаются из ссылки; для частного CA его явно задают
на своей машине через `--ca-cert`. Ссылка не может выключить проверку TLS.
При импорте её учётные данные используются вместо переменных окружения.

## Формат версии 1

`vetroff://` + JSON в base64url без `=`. Без пути, query, fragment и userinfo.
JSON использует UTF-8 и постоянные английские имена полей:

```json
{
  "v": 1,
  "servers": ["https://node-a.example", "https://node-b.example"],
  "username": "example-user",
  "password": "example-only-password",
  "tls": "go",
  "balance": "failover",
  "bond": true,
  "pipeline": "auto",
  "padding": false,
  "connect_timeout": "15s",
  "attempt_timeout": "5s"
}
```

Для TLS допустимы `go`/`nss`; режимов распределения — `failover`, `round-robin`,
`least-active`; конвейера — `auto`, `4`, `8`. Без `discover` для `bond` нужны хотя бы две ноды;
совместное включение с `padding` запрещено. NSS-ссылка требует подходящей сборки
на машине клиента, скрытой замены на Go нет.

Максимум ссылки — 16 КиБ, имени пользователя — 256 байт, пароля — 1024 байта.
Серверы только HTTPS без пути кроме `/`, учётных данных в URL и повторов адресов.
Лимит установки в ссылке — до двух минут, попытки — до 30 секунд; значения
положительные, при `bond` попытка не короче 100 мс. Значения по умолчанию — 15/5 с.
Неизвестные поля/версии, дубликаты ключей, варианты регистра имён полей и лишние
JSON-объекты отклоняются. Ссылка не содержит флагов сервера, файловых путей,
отключения проверки сертификатов и произвольных команд.

Проверки охватывают несколько нод, IPv6, русские учётные данные, спецсимволы,
неоднозначный JSON, ограничения размера, ошибки без утечки содержимого и фаззинг
декодера. CLI проверен на генерации и запуске локального слушателя через stdin.

## Встроенный транспорт

Поле `transport`: `h2-connect` (по умолчанию), `h2-post`, `wss`, `h3-post`.
Экспорт: `share --transport wss`; автоматическая подготовка: `setup --transport wss`.
NSS поддерживает первые три режима; `h3-post` вместе с `tls:nss` отклоняется.
Профиль не запускает внешние программы. Старые ссылки сохраняют H2 CONNECT.
См. [настройки и ограничения](NATIVE-TRANSPORTS.md).
