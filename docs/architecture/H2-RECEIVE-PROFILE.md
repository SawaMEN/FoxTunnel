# Экспериментальный профиль приёма HTTP/2

**Русский** | [English](H2-RECEIVE-PROFILE.en.md)

Добавлен `--h2-receive-profile firefox-158`: реальные окна HTTP/2 и таблица
декодирования HPACK настраиваются по [живому замеру Firefox 158](../research/WEB-PROFILE.md).
Профиль включается явно; по умолчанию остаётся `default`. Это часть поведения H2,
не реализация Firefox TLS/Necko и не доказательство браузерной неотличимости.

```sh
./foxtunnel client --link-file connection.txt --h2-receive-profile firefox-158
```

Профиль — локальная настройка этого запуска клиента: в ссылку/setup он не
записывается. Совместим с H2 CONNECT/POST и тремя режимами XHTTP на Go/NSS; сервер
менять не требуется. Работает для разных SNI/pin и адресов discovery. Настраивается
до включения bond/discovery. Внутренний H2 внутри XHTTP не изменяется. WSS/H3 и
неизвестное имя дают ошибку без автоматического переключения.

| Параметр | По умолчанию | firefox-158 | Замер Firefox |
|---|---|---|---|
| Окно потока | 4194304 | 131072 | 131072 |
| Таблица HPACK decoder | 4096, явно не объявляется | 65536 | 65536 |
| Максимальный H2-фрейм | 16384 | 16384 | 16384 |
| Начальное приращение окна соединения | 1073741824 | 12517377 | 12517377 |
| Полный начальный бюджет соединения | 1073807359 | 12582912 (12 МиБ) | 12582912 |

Значения управляют настоящим flow control и HPACK, а не подменяются в готовых
фреймах. По мере чтения приложением стек обновляет окна. Go использует
`http.Transport.HTTP2`; NSS шифрует данные, а x/net/http2 получает конфигурацию
через `ConfigureTransports` и собственный пул с NSS dial. Проверка сертификатов
и ALPN только H2 сохраняются.

В Go 1.26.9/x/net v0.61.0 настройка соединения означает добавочный бюджет к 65535;
wire-тест проверяет реальное приращение, чтобы обновление среды не изменило
профиль незаметно. Окно — бюджет потока, а не предел всей памяти процесса.
На высоком RTT меньшие окна могут снизить скорость: нужна проверка своей нагрузки.

Сохраняются отличия: SETTINGS идут в порядке
`2=0,4=131072,5=16384,6=10485760,1=65536`, у Firefox было
`1=65536,2=0,4=131072,5=16384`. Лимит заголовков ответа 10 МиБ не снят.
TLS/ALPN, HPACK encoding, порядок заголовков, приоритеты, возобновление и поведение
соединений пока не воспроизводят Firefox. H2 зашифрован при передаче; совпадение
этих параметров на сервере само по себе не доказывает сходства внешнего трафика.

Проверено на Go/NSS: реальные значения на проводе в пяти транспортах; четыре
потока по 4 МиБ через одно внешнее соединение с обновлением бюджета; отмена и
закрытие relay; отказ CA/SNI/pin до авторизации; откат несовместимой настройки;
сохранение профиля при пересоздании TLS-политик; импорт ссылки из stdin с локальным
профилем без вывода секретов.

Новые [Go](../measurements/2026-10-18/foxtunnel-go-firefox158-receive.json) и
[NSS 3.98](../measurements/2026-10-18/foxtunnel-nss-firefox158-receive.json) отчёты
сняты на локальном XHTTP packet-up echo 64 КиБ. Для `ft-webprofile` добавлен тот же
флаг; полные команды в английской версии. Сравнение `--strict` с Firefox всё ещё
завершается ошибкой: оставшиеся различия не скрываются.

Короткие loopback-замеры Go TLS (по два прогона 500 мс, 1 МиБ SOCKS echo) шумные:
CONNECT default 259,82–348,32 МБ/с, профиль 284,20–321,72; packet-up default
60,98–94,14 МБ/с, профиль 34,44–99,50. Преимущество скорости, Интернет и NSS этими
числами не установлены. Следующие задачи — Mozilla TLS/клиентский стек, одинаковые
нагрузки с RTT/потерями и полевые испытания операторов РФ. Обход ТСПУ не подтверждён.
