# Быстрый старт

[На главную](../README.md) · [English](START.en.md)

Это единственное руководство, которое нужно для первого запуска FoxTunnel. Для начала используйте **обычный TCP/SOCKS5**, без UDP, TUN, нод и экспериментальных профилей.

## 1. Подготовка

Нужно:

- Linux-сервер с доступом из Интернета, доменным именем и DNS-записью.
- Открытый входящий **TCP-порт 443** (для HTTP/3 отдельно потребуется UDP).
- Действительный TLS-сертификат **для этого домена** и его закрытый ключ.
- Клиентский компьютер с FoxTunnel.

FoxTunnel **не получает сертификаты, не настраивает DNS и firewall**. Используйте свой CA/ACME-процесс и продлевайте сертификат вовремя.

## 2. Установка

**Способ А — готовый архив.** Откройте [Releases](https://github.com/SawaMEN/FoxTunnel/releases), выберите архив под свою ОС и архитектуру, проверьте контрольную сумму/метаданные релиза, распакуйте весь комплект. Если в архиве есть папка \`lib/\`, **не отделяйте её от программы**.

**Способ Б — из исходников.** Установите Go 1.26+ и в корне репозитория выполните:

~~~bash
go build -o foxtunnel ./cmd/foxtunnel
./foxtunnel version --json
~~~

Обычная Go-сборка не содержит Neqo или NSS. Для них нужна отдельная Linux-сборка с нативными библиотеками. Не выбирайте \`--engine mozilla\` для обычной Go-сборки.

## 3. Настройте сервер

Замените \`vpn.example.com\` на **свой домен**, пути сертификатов — на настоящие. Показанные имена не действуют сами по себе.

~~~bash
./foxtunnel setup \
  --server https://vpn.example.com \
  --cert /etc/ssl/foxtunnel/fullchain.pem \
  --key /etc/ssl/foxtunnel/privkey.pem \
  --out server-config

./foxtunnel server --config server-config/server.json
~~~

\`setup\` проверяет сертификат и формирует защищённые файлы:

| Файл | Для чего |
|---|---|
| \`server-config/server.json\` | Конфигурация сервера; хранить на сервере |
| \`server-config/connection.txt\` | Настройки подключения и **секрет** клиента |
| \`server-config/node.json\` | Описание узла для экспериментального кластера |

Не размещайте эти файлы в публичной папке сайта. Серверная конфигурация и закрытый ключ никогда не передаются клиенту.

Для долгой работы настройте процесс как службу ОС. При остановке терминала показанный запуск может завершиться.

## 4. Запустите клиент

Безопасно скопируйте **только** \`connection.txt\` на клиент. Например, в его личную директорию с доступом только для владельца.

~~~bash
./foxtunnel client --link-file connection.txt
~~~

В приложении включите SOCKS5:

- адрес: \`127.0.0.1\`;
- порт: \`1080\`;
- дополнительные логин и пароль к локальному SOCKS5 не нужны.

**Это прокси для настроенных приложений**, а не автоматический перехват всего трафика ОС. Если приложение умеет отправлять DNS через SOCKS5, включите соответствующий режим, чтобы избежать локального DNS при работе с ним.

## 5. Проверьте

Убедитесь, что сервер работает и клиент не выводит ошибку TLS/авторизации. Проверьте соединение в приложении с заданным SOCKS5. Для командной проверки можно воспользоваться \`curl\`:

~~~bash
curl --socks5-hostname 127.0.0.1:1080 https://example.com/
~~~

\`--socks5-hostname\` отправляет DNS-имя через прокси, а не разрешает его локально. Это проверка одного приложения, **не гарантия** отсутствия других системных соединений.

## Если не работает

| Симптом | Что проверить |
|---|---|
| Ошибка сертификата | Домен, срок действия сертификата, полную цепочку, доверенный CA и SNI |
| Клиент не подключается | DNS, TCP 443, firewall, доступность сервера, правильный файл подключения |
| Авторизация отклонена | Не перепутаны ли файлы подключения, не менялись ли серверные учётные данные |
| SOCKS5 работает, но сайт нет | Настройку прокси в приложении, DNS через SOCKS5 и запрет назначения на сервере |
| HTTP/3 не работает | Доступность UDP-порта, совместимую сборку/транспорт; начните с HTTP/2 |
| \`--engine mozilla\` выдаёт ошибку | В вашей сборке, вероятно, нет требуемых NSS/Neqo |
| Приложения идут мимо туннеля | Это обычное поведение без явно заданного SOCKS или отдельно настроенного TUN |

Для своего CA клиент может указать \`--ca-cert /path/to/ca.pem\` при прямой конфигурации; публичное имя сертификата всё равно должно проверяться. При подключении с \`--link-file\` проверяйте допустимые сочетания дополнительных флагов командой \`foxtunnel client --help\`.

## Позже: экспериментальные функции

**Mozilla (Linux amd64 NSS + Neqo):**

~~~bash
./foxtunnel client --engine mozilla --link-file connection.txt
~~~

Известная экспериментальная сборка — [v0.1.0-alpha.2](https://github.com/SawaMEN/FoxTunnel/releases/tag/v0.1.0-alpha.2), сделанная до последнего слияния в \`main\`. Режим не обещает сетевой отпечаток Firefox и сохраняет транспорт из файла подключения.

**UDP:** при подготовке сервера добавьте \`--enable-udp\`, а клиент запустите с \`--enable-udp\`; для длительного UDP-потока добавьте клиенту \`--udp-stream\`.

**Системный VPN:** TUN, маршруты, DNS и kill switch принадлежат приложению-хосту. Встроенный TUN удалён. См. [контракт интеграции](INTEGRATION.md).

Подробности этих режимов — в [Возможностях и настройках](FEATURES.md).
