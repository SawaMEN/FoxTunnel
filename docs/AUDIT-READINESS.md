[Разработка](DEVELOPMENT.md) · [Эксплуатация, этап 7](OPERATIONS.md) · [Wire draft](reference/WIRE-DRAFT-0.md)

Этап 8 продолжает восьмиэтапный план после эксплуатационных проверок. Старая нумерация файлов CI `stage8`–`stage11` относится к отдельной лабораторной серии. Неподтверждённый подписанный/notarized выпуск этапа 7 остаётся отдельным открытым пунктом. Реальные VDS и WAN-испытания необязательны для этой реализации; заявления об операторах или обходе ограничений всё равно требуют соответствующих измерений.

## Рабочий чек-лист этого этапа

| № | Проверка | Что должно быть подтверждено |
|---|---|---|
| 1 | Реестр доказательств | Хеши входных файлов, сценарий/границы, известный source commit либо явное отсутствие привязки; пропуски не превращаются в совпадения |
| 2 | Внешняя SDK-интеграция | Отдельный Go-модуль без `internal` импортов; обычный HTTP-клиент через прямой dial и SOCKS5h, проверяемый payload, отмена, TLS и авторизация |
| 3 | Материалы для аудита | Идентичность checkout, признак грязного дерева, хеши lockfiles и карта поверхностей/границ доверия |
| 4 | Автоматические нативные проверки | Linux/macOS/Windows исполняют SDK-тесты; CI требует все 22 обязательных сценария и сохраняет агрегаты |
| 5 | Начальные fingerprint-метаданные в общем стенде | Firefox/FoxTunnel/NaiveProxy, TLS/H2 и endpoint-decoded QUIC/H3, закреплённые версии; методы приложений различаются |
| 6 | Независимая проверка безопасности | Внешний рецензент, определённый commit/объём, отчёт и разбор замечаний |

Пункты 1–5 реализованы в указанном ограниченном объёме; [новые измерения](NATIVE-BACKENDS.md) не подтверждают полную эквивалентность нагрузки. Результат CI оценивайте на конкретном коммите. Пункт 6 остаётся открытым. Подготовка материалов не является независимым аудитом. Пример потребителя SDK не означает, что FoxTunnel уже встроен в Hiddify, sing-box, Xray или другой сторонний продукт.

## Реестр и проверка происхождения

[`evidence/registry.json`](evidence/registry.json) перечисляет только отобранные публичные файлы из `measurements/`. Каждый вход связан с SHA-256, типом наблюдения, субъектом, областью измерения и source commit. У исторических TLS/H2-записей commit не восстанавливается задним числом: `source_commit: null`. Длительный native-отчёт сохраняет настоящий head и synthetic checkout этапа 7.

Проверка отвергает изменения байтов без обновлённого проверенного хеша, выход за каталог измерений, symlink в компонентах пути, слишком большие файлы, повторные JSON-ключи, неизвестные поля реестра и неверные типы. Для native-отчёта дополнительно проверяются три runner, длительность, счётчики, факт отказа/восстановления и исходные бюджеты ресурсов/времени. Метка `passed` не заменяет проверку чисел. Передвинуть H2-запись в слот QUIC/H3 нельзя.

Хеш удостоверяет соответствие байтов **проверенному реестру**, а не независимость автора, свежесть результата или истинность всех наблюдений. Изменение хеша в PR — изменение доказательной базы, которое требует предметного review. Скрипт не обращается к сайтам измерений и не запускает содержимое реестра.

## Пакет для рецензента

Из корня checkout, в новый файл вне репозитория:

~~~bash
python3 scripts/evidence_bundle.py --out /private/new-audit-handoff.json
~~~

Каталог вывода должен существовать; существующий файл не перезаписывается. Unix-файл создаётся с правами 0600; на Windows используйте закрытый каталог с подходящими ACL. Экспорт содержит только выбранные протокольные поля, агрегаты, относительные имена публичных входов и хеши. Локальные конфигурации, ключи, pcap и журналы процессов туда не копируются.

`checkout_commit` и `worktree_dirty` относятся к checkout, в котором сформирован пакет. Исторические измерения внутри имеют отдельную идентичность. CI записывает результат вне рабочего дерева и требует `worktree_dirty: false`. Хеши `go.mod`, `go.sum`, внешнего модуля, обоих Cargo.lock и Mozilla/Neqo/Naive capture lockfiles фиксируют входы зависимостей. Это **не resolved SBOM**, не полный состав динамических библиотек и не результат vulnerability scan. Известные Go-уязвимости проверяет существующий `Tests` workflow; нативные библиотеки требуют отдельного анализа для выбранной сборки.

Пакет сохраняет `independent_security_audit: not_provided`. Все шесть новых startup captures зарегистрированы: `all_six_captures_present: true`. [Происхождение](measurements/2026-10-21/wire/provenance.json) связывает их с CI и исходным manifest. Firefox source commit неизвестен, его archive/executable hashes сохранены. Выбранные поля FoxTunnel и NaiveProxy отличаются от Firefox; `metadata_equal: false`. Полная эквивалентность сценариев не подтверждена. Даже совпадение всех выбранных метаданных само по себе не доказывает неразличимость на сети.

## Внешний потребитель SDK

[`integration/external`](../integration/external/) — отдельный модуль с импортом только публичного пакета FoxTunnel. Локальный `replace` указывает на проверяемый checkout; пример не заявляет совместимость произвольных версий. Для реального встраивания закрепляйте проверенный commit/release и переносите свои CA, жизненный цикл и лимиты явно.

| Транспорт FoxTunnel | `http.Transport.DialContext` | `http.ProxyURL(socks5h://…)` |
|---|---|---|
| h2-connect | HTTPS/H2 POST, отмена, закрытие | Те же проверки |
| h2-post | Те же проверки | Те же проверки |
| h3-post | Те же проверки + сервер наблюдает реальный HTTP/3 | Те же проверки + реальный HTTP/3 |
| wss | Те же проверки | Те же проверки |
| xhttp-packet-up | Те же проверки | Те же проверки |
| xhttp-stream-up | Те же проверки | Те же проверки |

Это 12 позитивных сценариев. Ещё четыре проверяют отказ неверного TLS hostname и пароля через H2/H3 до достижения приложения. TLS приложения проверяется отдельно от TLS прокси. Внутренний HTTP/2 приложения — обычный `net/http`, а не собственный wire-протокол FoxTunnel. Отмена наблюдается и приложением, и клиентом. HTTP/3-сервер использует публичный `http.Handler` FoxTunnel и quic-go; владелец приложения отвечает за UDP/TCP listeners и сертификаты.

~~~bash
cd integration/external
go test -race -json ./... -count=1 -timeout=90s > /private/new-sdk-events.jsonl
cd ../..
python3 scripts/sdk_evidence.py --input /private/new-sdk-events.jsonl \
  --out /private/new-sdk-summary.json
~~~

Сводка требует события `run` и `pass` для всех 22 конкретных тестов и успешное завершение пакета. Пропуск, потерянный сценарий или отказ не засчитываются. В артефакт CI попадают имена проверок, source commit, native OS, признак грязного дерева и хеш событий; сырые события не сохраняются как артефакт. Обычный журнал CI содержит диагностику этих лабораторных тестов. Данные событий сами по себе не являются цифровой подписью: сверяйте их с доверенным CI run. NSS/Neqo и TUN не входят в эту матрицу. Этап 7 добавляет четыре проверки версии/событий/отмены SDK и два реальных process-host H2/H3 сценария: всего 22 обязательных случая. CI строит настоящий CLI, а отсутствие process binary считается пропуском и отвергается evidence gate.

## Объём независимого review

| Граница / поверхность | Что проверять | Существующие материалы |
|---|---|---|
| Недоверенная сеть → TLS → proxy credentials | CA/hostname/SPKI, TLS до авторизации, терминальные TLS-ошибки, отсутствие replay | [Security hardening](SECURITY-HARDENING.md), `internal/tlsidentity`, `internal/tunnel/setup.go` |
| Локальное приложение → SOCKS / SDK | Авторизация/доступность listener, лимиты, отмена, потоковые deadline и освобождение ресурсов | `foxtunnel.go`, `internal/tunnel/socks_*`, внешние SDK-тесты |
| Proxy user → выходная сеть | Запрет private/link-local адресов по умолчанию, DNS/rebinding, ограничения UDP, общие квоты и долговечность учёта | [Возможности](FEATURES.md), `internal/access`, wire draft |
| Сервер / клиент → фоновые worker и кэши | Закрытие незавершённых потоков, H3 generations, отмена, гонки и лимиты | [Эксплуатация](OPERATIONS.md), Go race tests |
| NSS/Neqo FFI → Go/Rust/C | Время жизни буферов, ABI, callback/race safety, лимиты памяти, pinned runtime и реальный состав бинарника | `internal/nsstls`, `internal/neqo`, `rust/neqo-bridge`, lockfiles |
| Файл выпуска → установленный executable | Доверенный источник, подпись происхождения, path traversal, хеши библиотек, атомарность, права/ACL и откат | [Эксплуатация](OPERATIONS.md), `scripts/release_verify.py`, `scripts/deploy_cli.py` |

Review следует привязать к полному commit SHA, build tags, runtime/ОС и подтверждённым сценариям. Отдельно перечисляются исключённые компоненты, воспроизводимые находки, уровень риска, исправляющий commit и повторная проверка. Для чувствительных находок сначала согласуйте приватный канал с владельцем репозитория; секреты и пользовательские захваты в публичный issue не помещайте. Внешние системы без разрешения владельца не входят в проверку.

CI `Evidence and external SDK integrations` исполняет нативную матрицу и публикует `foxtunnel-audit-handoff` / `external-sdk-<runner>` на семь дней. Долгосрочные входы остаются в реестре; новые результаты добавляются отдельным review с хешами и источником.
