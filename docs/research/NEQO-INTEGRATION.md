# Neqo / HTTP/3: план интеграции

**Русский** | [English](NEQO-INTEGRATION.en.md)

## Подтверждённая архитектура

Firefox использует [Neqo](https://github.com/mozilla/neqo) (Rust, QUIC/HTTP/3/QPACK, NSS) через Necko и `neqo_glue`. Эксперимент `experiments/neqo-ffi` создаёт QUIC Initial через Neqo, однако рабочий H3 FoxTunnel **пока не использует Neqo**: H3 POST — `quic-go` + Go TLS; NSS обслуживает TCP-транспорты H2/WSS/XHTTP. Замена одного TLS-движка не переносит сетевой стек Firefox.

Официальная документация: [HTTP/3 в Firefox](https://firefox-source-docs.mozilla.org/networking/http/http3.html), [репозиторий Neqo](https://github.com/mozilla/neqo).

## Этапы отдельного экспериментального backend

1. Зафиксировать проверенный тег Neqo, Cargo.lock, точные исходники, лицензии и совместимую NSS-версию. Не загружать непроверенные динамические библиотеки при работе туннеля.
2. Реализовать **клиентский** Rust FFI-адаптер к `neqo-http3` / `neqo-transport` (первоначально Linux amd64): явное управление UDP, контекстом, потоками запросов/ответов и закрытием. Не смешивать структуры Rust, C и Go напрямую; ABI должен быть минимальным, версионированным и проверяемым.
3. Настроить проверку идентичности: системное + дополнительное доверие, обязательный SNI, SPKI pin, ALPN h3. Не разрешать передачу заголовков авторизации до успешной проверки. Отмена запроса должна завершать QUIC-операции без утечек горутин/памяти.
4. Проверить `h3-post` против **существующего** Go-сервера H3 FoxTunnel: повторное использование соединений, half-close, большие записи, конкуренция, потери/RTT, запрет UDP, обработка отмены. Независимо сравнить с Firefox по внешнему packet capture, не обещая совпадение отпечатка.
5. Только после прохождения тестов включить opt-in `--quic-backend neqo` и `-tags neqo`. Публичные NSS-релизы **не** должны автоматически включать недоведённый Neqo. При явном выборе Neqo отсутствие поддержки — ошибка, а не тихий переход на `quic-go`.

## Текущее решение

* Для H3 используем работоспособный `quic-go` без заявления о Mozilla QUIC.
* `--tls-backend auto` выбирает NSS для TCP при его наличии и Go QUIC для H3, а `--tls-backend nss --transport h3-post` отклоняется.
* Go TLS остаётся диагностическим backend, но не отдельным публикуемым релизом.
* Neqo-сервер Mozilla является экспериментальным и **не** заменяет сервер FoxTunnel без отдельного аудита.
* «Лучше Firefox/NaiveProxy» или «обходит ТСПУ» можно утверждать только после корректных измерений, сейчас доказательств нет.

Экспериментальный Rust/C ABI v2 доступен в [experiments/neqo-ffi](../../experiments/neqo-ffi/README.md): Neqo обрабатывает UDP и таймеры, тестируется с локальным Go HTTP/3-сервером; **любая аутентификация сертификата принудительно отклоняется**. Проверка CA/SPKI, HTTP/3-запросы и интеграция в основной Go-клиент ещё не реализованы.
