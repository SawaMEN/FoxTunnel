# Сравнение FoxTunnel и VLESS на одинаковой нагрузке

**Русский** | [English](TRANSPORT-COMPARISON.en.md) · [Исследования](README.md)

`scripts/compare_transports.py` — независимый Python 3.11+ стенд без сторонних зависимостей. Подключается к **уже запущенным локальным SOCKS5** FoxTunnel и Xray/VLESS, выполняет CONNECT до **одного и того же контролируемого TCP echo-сервера**, проверяет все возвращённые байты и записывает задержку установки, скорость и ошибки в JSON.

VLESS нужно называть вместе с транспортом: например VLESS + REALITY + Vision или VLESS + XHTTP + TLS.

## Изолированная лаборатория

1. Запустите echo-сервер **на общей выходной ноде**: `python3 scripts/echo_server.py --host 127.0.0.1 --port 9000`. Сервис без авторизации, не открывайте его в Интернет. В отдельной лабораторной сети доступно `--host LAB_IP --allow-public`, но только с ограничивающим firewall.
2. Запустите FoxTunnel с SOCKS5 на `127.0.0.1:1080`, а Xray с отдельным локальным SOCKS5 на `127.0.0.1:1081`, направленным через VLESS outbound. SOCKS5 слушают **только loopback**. Согласуйте VDS, маршруты, DNS, версию сервера и настройки нагрузки.
3. FoxTunnel по умолчанию запрещает обращения к удалённому loopback. `server --allow-private` допустим **только внутри доверенного изолированного стенда**, не в публичном прокси. Альтернатива — выделенный разрешённый echo-адрес с сетевыми ACL.
4. Адрес в `--target` интерпретируется **на удалённом выходе**. Доменное имя передаётся SOCKS5-серверу, локальный DNS для цели не вызывается.

```bash
python3 scripts/compare_transports.py \
  --proxy FoxTunnel=127.0.0.1:1080 \
  --proxy VLESS-Vision=127.0.0.1:1081 \
  --target 127.0.0.1:9000 \
  --rounds 20 --parallel 4 --warmup 2 \
  --bytes 4194304 --timeout 20 \
  --out comparison-001.json
```

Добавьте третий SOCKS5-вход для VLESS + XHTTP или запустите аналогичное сравнение отдельно. `--out` никогда не перезаписывает существующий JSON.

## Что измеряется

- `connect_p50_ms` и `connect_p95_ms`: TCP-подключение к локальному SOCKS5 и удалённая операция CONNECT. Клиенты могут повторно использовать ранее открытые TLS-сеансы.
- `payload_median_mbps` и `payload_p95_mbps`: **Мбит/с на один успешный echo-поток**, исключая установку соединения. Каждый полезный байт учитывается **один раз**, не дважды за отправку и ответ.
- `successful/attempted`, `failed`, ошибки и отдельные образцы: результат корректен только после проверки полного содержимого ответа. Скорость считается **только по успешным** потокам: всегда сопоставляйте её с процентом успеха.
- `--parallel N` запускает N одновременных потоков **одного** прокси; разные прокси тестируются последовательно внутри раунда. Приводимая скорость — не сумма N потоков. Порядок кандидатов чередуется между раундами.

## Ограничения

**Это не доказательство обхода ТСПУ, не тест TLS-отпечатка Firefox и не готовое измерение у российских операторов.** Измеряется вся цепочка SOCKS → клиент → транспорт → удалённый выход → echo. CPU/RSS, TCP-повторы и реальные потери пакетов пока не измеряются. Сходство с браузером проверяйте отдельно через `ft-webprofile` и внешний packet capture.

Для каждого результата сохраните рядом с JSON Git SHA FoxTunnel, версию Xray, профиль VLESS, backend Go/NSS/Neqo, параметры VDS и внешнего IP, MTU, ОС, регион/оператора, дату/время, RTT/потери, CPU/RSS и параметры теста. Повторяйте в разное время; проверяйте МТС, МегаФон, Билайн и T2 отдельно. «Белые списки» требуют проверки **конкретного IP** в конкретной сети. Захваты пакетов могут содержать приватные метаданные — не публикуйте их автоматически.

```bash
python3 -m unittest discover -s scripts -p 'test_compare_transports.py' -v
```

Офлайн-тесты используют **имитатор SOCKS5**, а не настоящий VLESS или FoxTunnel.
