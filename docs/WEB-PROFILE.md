# Измерение сходства с браузером

**Русский** | [English и команды воспроизведения](WEB-PROFILE.en.md)

FoxTunnel пока отличается от обычного браузера. Для работы над сходством добавлен
`ft-webprofile`: локальный TLS 1.3/HTTP2-стенд, который отдаёт Firefox тестовую
HTML-страницу или проверяет настоящий FoxTunnel через SOCKS, выбранный транспорт,
внутренний H2, авторизацию и локальный TCP echo. Проверка сертификата остаётся
включённой. Случайный путь, заголовки и padding сами по себе не доказывают сходства.

Отчёт содержит несекретные поля ClientHello, начальные SETTINGS в исходном порядке,
WINDOW_UPDATE соединения, первые 512 заголовков клиентских H2-фреймов и первые
512 заголовков TLS-записей: направление, длину и относительное время. Превышения
лимита считаются отдельно. JSON не содержит HPACK, паролей, имён хостов, ключей,
идентификаторов сессии или передаваемых данных. Ограниченная копия ClientHello
используется временно для завершения TLS.

Это **TLS-записи, а не TCP-пакеты**. Время относится к чтению/записи сокета на
стенде, а не к приходу пакетов на интерфейс. Заголовок записи может быть замечен
до получения всего тела. H2 виден здесь благодаря расшифровке на контролируемом
сервере; посредник в сети не читает зашифрованные SETTINGS и HTTP-заголовки.
HTTP/1.1, H3, DNS, сегментация TCP, несколько соединений страницы, возобновление
TLS, совместимость ECH, мобильный Firefox и реальные операторы этим тестом не
проверяются.

Стенд принимает только явный loopback IP; используйте отдельный профиль браузера
и временный доверенный CA. Ожидание подключения ограничено 60 секундами, handshake
— 10 секундами, измерение — максимум 30 секундами, по умолчанию 3. Тестовые
учётные данные публичны; это не сервер для развёртывания. Полные команды выпуска
локального CA, запуска Firefox, Go/NSS-клиента и сравнения приведены в английской
версии. `--strict` завершается ошибкой при отличиях TLS/начальных H2-полей.

## Реальный замер 18 октября 2026

[Исходные JSON](measurements/2026-10-18/) сняты на одном Linux amd64: официальный
Firefox 158.0 с NSS 3.130, Go 1.26.9 и системная NSS 3.98. Firefox использовал
новый профиль и локальный CA, фоновые проверки сети и телеметрия были отключены.
В контейнере потребовались отдельные overrides sandbox для этого изолированного
headless-процесса: это не обычная настольная среда и не рекомендация отключать
защиту повседневного браузера. Клиенты этой ветки передавали 64 КиБ через XHTTP
packet-up с проверкой echo. Дополнительный замер загружает в FoxTunnel именно
библиотеки NSS 3.130 из Firefox.

| Признак | Firefox 158 | FoxTunnel Go | FoxTunnel NSS 3.98 | FoxTunnel NSS 3.130 |
|---|---|---|---|---|
| Предлагаемый ALPN | h2, http/1.1 | h2 | h2 | h2 |
| Предлагаемые версии TLS | 1.3, 1.2 | 1.3 | 1.3 | 1.3 |
| Длина тела TLS-записи ClientHello | 1882 Б | 1487 Б | 194 Б | 1390 Б |
| Начальные SETTINGS: ID=значение | 1=65536, 2=0, 4=131072, 5=16384 | 2=0, 4=4194304, 5=16384, 6=10485760 | как у Go | как у Go |
| Приращение окна соединения | 12517377 | 1073741824 | 1073741824 | 1073741824 |

Различаются также наборы шифров/групп, порядок расширений и key shares. Даже та
же версия NSS не воспроизводит настройки Firefox и HTTP2-стек Necko. Настоящее
согласование и управление окнами должны соответствовать объявлениям; нельзя
рекламировать неподдерживаемый fallback ради совпадения строки. Политика TLS
1.3-only сохраняется до отдельного обоснованного изменения.

Сценарии HTML и echo имеют разный объём и назначение: суммарное количество записей
не является оценкой качества маскировки. Следующий шаг — закреплённый Mozilla
клиентский стек/конфигурация, проверка реального flow control, HPACK и повторного
использования соединений, затем повторный замер. После этого нужны одинаковые
сценарии страниц/потокового обмена, внешний захват пакетов, сравнение размеров,
времени и числа соединений при одинаковых RTT/потерях. Наконец — испытания на
российских операторах с учётом неудачных подключений. Совпадение JA3 или этого
локального профиля не доказывает обход ТСПУ; такой обход пока не проверен.
