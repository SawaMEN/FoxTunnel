# Следующие этапы FoxTunnel

**Русский** | [English](NEXT-STEPS.en.md)

База анализа: main `b56f8e4` от 18 октября 2026. Уже реализованы семь транспортов,
NSS TLS на Linux, XHTTP path/Host и конвейер packet-up, частичный H2 receive profile,
SDK, подготовка кластера и ограниченное восстановление bond через общий выход.
Живые Firefox 158/Go/NSS измерения сохранены; полного сходства с Firefox нет.

| Этап | Работа | Критерий готовности |
|---|---|---|
| 1. Воспроизводимая база | Проверка содержимого архивов, закреплённая сборочная среда, согласованные документы и совместимость | Две Linux NSS-цели проходят index и offline verify; Go/NSS/SDK проверки на том же commit; экспериментальный тег только после проверки |
| 2. Mozilla TLS/H2 | Устранение измеренных различий NSS и H2; resumption и изоляция идентичностей; решение о нужных компонентах Mozilla | Воспроизводимый отчёт совпадений/различий с закреплённым Firefox/ОС, одинаковые сценарии и сохранённые TLS-проверки |
| 3. Передача | Coalescing мелких записей, профиль Go/C и копирований, постоянные bond-каналы с ограниченными окнами | Один стенд RTT/потерь: скорость/p95/CPU/память; порядок и отсутствие дубликатов при отказах; ограниченные очереди |
| 4. Neqo | Клиент Mozilla QUIC/H3 против независимого сервера, контролируемый H2 fallback | Передача/CA/SNI/pin, тесты запрета UDP и времени переключения; без ослабления политики TLS |
| 5. Доступ | Раздельные пользователи/отзыв/ротация, квоты, частотные лимиты, безопасная диагностика | Отзыв одного пользователя не затрагивает других; ресурсы ограничены; секретов нет в журналах |
| 6. Полный VPN | UDP, затем TUN, маршруты, DNS/IPv6, kill switch на первой целевой ОС | Политики TCP/UDP и тесты утечек/отказов/сна/смены сети |
| 7. Эксплуатация | Нативные проверки ОС, длительные нагрузки, сертификаты, остановка, обновление/откат, подписи | Воспроизводимая установка и восстановление на реальных целевых системах |
| 8. Подтверждение и интеграции | Сравнение NaiveProxy, полевые испытания операторов, внешний аудит, адаптеры клиентов/панелей | Опубликованные измерения, включая отказы; проверенные интеграции с закреплённой версией |

На этапе 1 добавлены независимая проверка комплекта без запуска бинарников и
[правила совместимости/первого тега](../reference/COMPATIBILITY.md). CI собирает, но не публикует
релиз на обычной ветке/PR. Публикация требует явного тега либо изменения release-request через main.
Linux NSS-архивы включают hash-pinned библиотеки Mozilla; публичных macOS/Windows и Go-only архивов нет. Текущее наличие релиза проверяется в GitHub Releases, а не выводится
из существования workflow.

Следующая конкретная задача этапа 2: по [WEB-PROFILE](../research/WEB-PROFILE.md) разделить
TLS/ALPN/key shares, SETTINGS/HPACK и жизненный цикл соединений; для каждого
различия закрепить измерение и решение. Профиль приёма уже меняет настоящие окна,
но не порядок SETTINGS или весь стек Necko. Одинаковая версия NSS недостаточна;
полный перенос Necko пока не принят как обязательная архитектура.

Сравнение HTML Firefox с TCP echo не оценивает маскировку. Нужны одинаковые
нагрузки, внешний захват пакетов, RTT/потери, повторные соединения и разные ОС.
Локальные ускорения packet-up/bond не устанавливают преимущества в Интернете.
Общий выход остаётся точкой отказа; перенос потерянного выходного TCP-сокета не
реализован. Полевые измерения можно начинать раньше и повторять после изменений.

Управление пользователями и платформенные проверки можно делать параллельно
Mozilla-работе. ECH/REALITY, XMUX, разные адреса направлений XHTTP и произвольные
CDN — отдельные эксперименты, не условия первого тега. Совместимость XHTTP с
внешними реализациями требует независимых wire-тестов. Автоматический выбор
транспорта вводится после измерений, а не по названию протокола.

[Neqo](https://github.com/mozilla/neqo) рассматривается сначала как клиент (см. [план интеграции](../research/NEQO-INTEGRATION.md));
экспериментальный сервер Mozilla не заменяет сервер FoxTunnel в production.
Стабильные адаптеры sing-box/Hiddify/3x-ui следуют после фиксации контрактов.
Ни один этап сам по себе не доказывает устойчивости к ТСПУ.
