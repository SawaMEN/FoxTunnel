# Повторная проверка 27 октября 2026

База: `99029f8906c24919018f2a261a50a1596eecbb9c` (`main`).
Среда: Linux amd64, Go 1.26.10, Python 3.12, системный NSS 3.98.
Это проверка исходников и локальных контрактов, не независимый аудит безопасности.

## Исправления

1. UDP назначения использовали TCP-обёртку квот. При остатке квоты меньше
   пакета запись отправляла префикс, а чтение возвращало усечённый пакет
   как успешный. Добавлен `access.DialDatagram`: запись резервирует полный
   пакет, чтение учитывает фактический размер и отвергает пакет целиком,
   если он не помещается в квоту. Общие блокировки, отзыв доступа, лимиты
   соединений и долговечный учёт сохранены. TCP использует прежний путь.
   Новый путь также сохраняет пустые пакеты и не делит большие пакеты
   на TCP-чанки по 32 КиБ. Оба UDP endpoint используют общий dial-путь.
2. UDP mock в Python-тестах закрывал сокеты до остановки рабочего потока.
   Это порождало фоновые `Bad file descriptor` при формально успешных тестах.
   Теперь поток останавливается до закрытия сокетов.
3. README на двух языках и инструкции установки/эксплуатации описывали
   старый ARM64 NSS-only архив ветки `xfd`. Они приведены в соответствие
   с текущим workflow: единые NSS + Necko архивы amd64 и arm64.
   Это описание сборочного контракта, а не проверка опубликованных файлов.

## Воспроизведение и регрессии

Три теста `TestDatagram*` используют настоящие loopback UDP-сокеты.
Подстановка прежнего `access.Dial` воспроизводит все три отказа: частичная
запись, частичное чтение и разделение 40000 байт на пакет 32768 байт.
С `DialDatagram` тесты проходят пять повторов под race detector.

`TestAccessUDPQuotaPreservesPacketsDirectAndCascade` дополнительно проверяет
HTTP UDP endpoint через прямой и SOCKS5-выход: ответ из пяти байт при общей
квоте девять байт отвергается, при квоте десять байт возвращается целиком.
Четыре сочетания проходят пять повторов под race detector. SOCKS5-выход —
локальный mock; эта проверка не использует внешний прокси.

## Не проверено этим запуском

- Настоящие Gecko/Necko и Rust/Neqo: соответствующие runtime и toolchain
  не собирались. Обычные Go-тесты пропускают нативные сценарии без runtime;
  прохождение пакета не означает прохождение этих сценариев.
- Native execution на ARM64, macOS и Windows: выполнена только кросс-сборка.
- WAN, мобильные сети, DPI, сравнение отпечатка с Firefox и длительная
  эксплуатационная нагрузка. Сохранённые исторические замеры не обновлялись.
- Опубликованные архивы, attestations и свежий результат GitHub Actions.
  Тесты упаковочных скриптов не заменяют проверку реального релиза.
