# SOCKS5-каскад

[Документация](README.md) · [Настройки](FEATURES.md)

Клиент → сервер VetroffProxy → SOCKS5 → следующий VPN → интернет.
Настройка применяется на сервере, который завершает туннель; для Bond — на общем hub.
Fallback-ноды и `bond-upstream` сами по себе такой выход не создают.

Добавьте к существующему приватному `server.json`:

```json
{
  "egress_proxy": "socks5://127.0.0.1:1080",
  "egress_dns": "1.1.1.1:53"
}
```

Остальные поля сохраните. Прокси и DNS задаются числовыми IP и портами;
DNS должен поддерживать TCP. Без `egress_dns` используется `1.1.1.1:53` через тот же прокси.
Авторизация: `socks5://user:password@127.0.0.1:1080` с URL-кодированием спецсимволов.
Проверка: `./vetroff check-config --config server.json`.

Аналоги CLI — `--egress-proxy`, `--egress-dns`; Go API — `EgressProxy`, `EgressDNS`.
Через SOCKS5 идут TCP всех транспортов, UDP v1/v2, Bond и DNS назначений.
Для UDP следующий узел должен поддерживать UDP ASSOCIATE.

При отказе прокси, DNS или авторизации **прямого выхода нет**.
Запрет приватных назначений сохраняется; имена проверяются перед передачей числового IP.
Эта настройка не перехватывает весь трафик процесса/ОС и соединения relay → hub.
SOCKS5 не шифрует данные: удалённый следующий узел требует защищённого транспорта.
